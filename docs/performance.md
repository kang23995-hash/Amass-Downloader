# 性能记录与测量边界

以下是 2026-11-18 同一开发机器上的历史测量，不代表所有网络环境，也不作为最低速度保证。源码仓库保留结论，不保留终端原始输出或大体积测试文件。

## ModelScope 直连短时对照

同一 URL、HTTP/1.1、自适应并发、实际写盘，每轮运行 20 秒后取消：

| 条件 | 平均 MB/s | 最后四个约一秒窗口 MB/s |
| --- | ---: | --- |
| 有界队列调整前 | 26.865 | 35.062 / 34.177 / 39.322 / 35.078 |
| 有界队列调整后 | 30.761 | 31.982 / 31.195 / 34.570 / 37.437 |

这不是完整文件均速，也不是受控网络实验。两轮网络状态可能不同，不能将全部差异归因于代码；短时超过 35 MB/s 不等于全程稳定 35 MB/s。

## 完整下载与可靠性

此前四轮 Rocky ISO（2,950,234,112 字节）含探测、落盘和 SHA-256 的完整平均速度分别为 23.83、23.63、17.56、15.60 MB/s，均通过官方 SHA 校验。其中 17.56 MB/s 是稀疏文件实验，因此该选项未默认开启；后续普通文件复验也降速，不能把波动单独归因于分配方式。

ModelScope 模型（4,683,071,264 字节）完成下载及官方 SHA-256 校验。期间为诊断与恢复缺陷做过中断，不将其包装成不中断的完整文件测速。

终端版交付时通过了 97 个常规测试、Clippy、原 CLI 生命周期回归，以及 Windows 原生终端中的粘贴、下载、暂停恢复、网络切换和文件 SHA 校验。GitHub CI 会重新执行自动检查。

## 重现

本地吞吐矩阵自动启动可控服务器，不依赖公网：

```powershell
cargo test --release -p rd-engine --test bench benchmark_matrix -- --ignored --nocapture
```

公网完整验收可使用 `tools/acceptance.ps1`，必须指定下载链接和发布者提供的 SHA-256。它会生成独立的、已忽略的 `diagnostics/` 测试数据；验收后可自行清理。与其他下载器比较时，应统一 URL、代理节点、磁盘、并发和测试时段，并交替运行多次。

所有速度使用十进制 MB/s；文件体积显示使用 MiB/GiB。
